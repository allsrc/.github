# Contributing to Allsrc projects

Thanks for helping. This is the default guide for Allsrc repositories. A repository with its own `CONTRIBUTING.md` (for example one that
describes a spec-driven workflow) follows that one instead; read it first.

## Before you start

- Check existing issues and pull requests so work is not duplicated.
- For anything larger than a small fix, open an issue to agree on the approach before writing code.
- Read the repository's README for how to set up, test and run it.

## Pull requests

- Branch from the default branch and keep the change focused.
- Add or update tests, and run the repository's checks before opening the pull request.
- Update documentation and the changelog when behavior changes.
- Use the pull request template: describe what changed and how you verified it.
- By contributing you agree your work is released under the repository's license.

## Conduct and security

- Be kind and follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
- Report vulnerabilities privately; see the [security policy](./SECURITY.md).
